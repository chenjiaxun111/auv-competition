# ZED—Jetson—NanoPi 三机联调测试报告

测试日期：2026-09-14

## 结论

无推进器条件下，真实 ZED 2i→Jetson YOLO/3D 感知→ROS 2 比赛状态机→运动桥接→NanoPi auvmaster 2.x→六路 PWM 软件目标链路已跑通。测试结束后独立回零验证通过，Jetson 无残留联调进程。

## 复测命令

先确认六个推进器均已物理断开，NanoPi `auvmaster` 正在运行，然后在 Jetson 上执行：

```bash
bash /home/auv/run_full_chain_bench.sh --allow-pwm --duration 30
```

测试同时在当前电脑浏览器实时查看 YOLO 画框、置信度、XYZ 和距离：

```bash
bash /home/auv/run_full_chain_bench.sh \
  --allow-pwm --duration 30 --web-preview
```

然后打开 `http://192.168.3.19:8080`。网页只读，默认约 10 FPS，不会发送控制指令；联调结束时会与 ZED 进程一起关闭。若要在 Jetson 本机显示器上查看，将 `--web-preview` 换成 `--jetson-view`。

报告自动保存在 `/home/auv/ros2_ws/bench_reports/<timestamp>/`，包括 ZED 日志、launch 日志、话题所有权、rosbag 和 `final-zero.json`。

## 联调中发现并修复的问题

1. `/auv/connected` 原先只在状态变化时发布，晚启动的监听者会错过；现以 2 Hz 周期发布。
2. Humble 的 `ros2 service type` 不支持 `--no-daemon`；已移除不兼容参数。
3. DDS 端点发现存在瞬时竞态；控制话题 1:1 检查改为限时重试并保存证据。
4. SSH 会话终止可能遗留子进程；ZED 和 ROS launch 现使用独立进程组并在 trap 中整组停止。
5. 搜索偏航原缩放到固件死区以内，无法验证非零混控；台架配置现映射为约 0.267，刚超过 `30/127` 死区。
6. ROS context 关闭与 RPC 工作线程发布诊断存在竞态；现在上下文无效时安全停止发布。

## 验证边界与下一步

这是 L4 无推进器台架验证。六路数值来自 NanoPi `propeller_power` 软件快照，尚未使用示波器或逻辑分析仪验证 PCA9685 引脚波形，也不能证明推进器物理方向。

现场画面没有被临时类别 `person` 识别的目标，所以本轮证明了真实空检测帧会驱动搜索分支，但没有验证球的三维对准、撞击时序或门的对准/穿越。下一步应优先训练 YOLOv8n 比赛模型，再用真球和门做同样的无桨视觉伺服联调。
