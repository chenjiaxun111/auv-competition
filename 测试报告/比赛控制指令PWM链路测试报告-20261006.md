# 比赛控制指令 PWM 链路测试报告（2026-10-06）

## 结论

在推进器动力物理断开的条件下，Jetson 按比赛实际接口发布 `/auv/control_command` 与 `/auv/motion_enable`，经 `rov_thruster_bridge`、JSON-RPC `move`、NanoPi 混控后，四个运动轴的正反方向均产生了符合当前推进器反转配置的六路软件 PWM 目标。

八个阶段均观察到非零回读；每段结束、测试结束、桥接停止和 NanoPi 心跳超时后的六路回读均为 0。未发现轴串扰、方向未反转、通信失败或软件目标无法回零的问题。

本次不能测量真实推进器转速，因为推进器动力已断开且系统没有 RPM 传感器或电调转速遥测。

## 实际测试链路

```text
geometry_msgs/Wrench /auv/control_command
    + std_msgs/Bool /auv/motion_enable
    → Jetson rov_thruster_bridge
    → HTTP/JSON-RPC move(x, y, z, yaw)
    → NanoPi auvmaster 混控
    → propeller_power 六路软件目标回读
```

- Jetson：`192.168.137.1`
- NanoPi：`192.168.137.219:8888`
- ROS 2：Humble，`ROS_DOMAIN_ID=96`
- 指令频率：20 Hz
- 指令幅值：比赛配置最大值的 25%
- 单方向持续时间：0.50 s
- 回读频率：10 Hz
- 现场测试工具：`/home/auv/competition_command_test.py`

### 轴隔离

- `surge`、`sway`、`yaw`：只有四台水平推进器产生非零目标；
- `heave`：只有左右两台中间推进器产生非零目标；
- 未观察到水平动作串入升沉推进器，或升沉动作串入水平推进器。

### 符号检查

NanoPi 当前配置将 `front_right`、`back_right` 和 `center_left` 标记为反转。考虑这些反转后：

- 前后、左右、升沉、偏航的正向符号均与当前混控配置一致；
- 每个轴的负向结果均完整反转；
- 左右幅值不完全对称，来源是当前各推进器不同的死区补偿和正反向动力比例，不属于本次发现的新故障。

## 停止与清理结果

- 每个动作阶段后：连续发送关闭使能与全零命令，六路回读全部为 0；
- 完整测试结束：`FINAL ZERO VERIFIED`；
- 远程终端中断后发现桥接子进程未随 SSH 会话自动退出，已单独发送正常中断并清除；
- 清除桥接后再次独立提交三次全零，六路回读全部为 0；
- 等待 NanoPi 3 秒心跳超时后，深度、航向和横滚闭环均为 `active=false`，PID 输出全部为 0；
- 最终 Jetson 无 `rov_bridge`、比赛控制器或测试发布器残留进程，NanoPi RPC 服务保持在线。

## 停止基准补充确认

现场随后确认：`1600 us` 是已经针对当前推进器/电调调整过的停转值，并且在手柄与上位机控制中已验证能够正常停转。因此不能把 `1600 us` 本身判定为故障。

仍需统一旧文档和部分测试工具中遗留的 `1500 us` 描述，避免调试人员把“软件相对零值”误认为绝对 `1500 us`。建议统一以下内容：

1. 固件停止脉宽；
2. 启动脉宽序列；
3. 测试工具显示的绝对微秒值；
4. 相关使用说明和测试报告。

启动阶段先输出 `1550 us` 约 500 ms 的行为尚未在本次断电测试中做真实推进器确认，后续受约束台架测试时应单独观察。

## 验证级别

本次为 L4：真实 Jetson、NanoPi、PCA9685控制程序和比赛通信链运行，但推进器动力物理断开，没有真实执行器动作。

本次证明软件控制链、混控符号、轴隔离和软件回零可用；不证明真实转速、推力方向、停止脉宽、电气波形或水下运动效果。
