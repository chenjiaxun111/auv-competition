# AUV 比赛目标标注工具使用说明

本说明供数据标注人员使用。任务是为 AUV 撞球和过门视觉系统标注水下图像，输出 YOLO 目标检测标签。

## 1. 只标注三个类别

类别编号和名称必须始终保持不变：

| 键盘按键 | 类别编号 | 类别名称 | 标注对象 |
|---:|---:|---|---|
| `1` | 2 | `blue_ball` | 比赛用蓝色撞击球 |
| `2` | 0 | `red_ball` | 比赛用红色撞击球 |
| `3` | 1 | `gate` | 比赛用红色 PVC 矩形门框 |

不增加其他类别，不修改编号顺序。一张图中有多个目标时，必须分别画框，不能用一个大框合并多个目标。

## 2. 比赛目标特征

根据 2026 年机器人水中巡游比赛规则：

- 撞击球分为红色和蓝色，球半径约 10 cm，悬浮于水中，距池底约 60 cm。
- 门框约为 70 cm × 50 cm，由红色 PVC 管组成矩形可穿越区域，并存在高低门布置。

水下颜色会受光照、距离、浑浊度和相机白平衡影响。红球可能呈橙色、暗红或褐红，蓝球可能呈深蓝或近似黑色。应结合球体形状、支撑杆和连续帧上下文判断，不要只凭单一像素颜色猜测。

## 3. 不要标注的物体

以下物体不属于三个目标类别，即使颜色或外形相似也不画框：

- 池底橙红色引导线。
- 红色圆环抓取物。
- 黄色或粉色高尔夫球抓取物。
- 红色投放区、收集框、陈列架和网筐。
- 池壁、池底、气泡、反光、阴影、人员、机器人结构和线缆。
- 球体下方的细支撑杆和门框下方的支撑腿。

含有上述干扰物但不含红球、蓝球或门框的图片，是有价值的负样本，应按 `N` 保存空标签，不要删除。

## 4. 边界框标注规范

### 4.1 红球和蓝球

- 边界框应紧贴可见球体的上、下、左、右外缘。
- 不将支撑杆、阴影、反光光晕或水泡包含在球框中。
- 球体边缘轻微模糊时，框住人眼可判断的球体轮廓，不要留大量背景边距。
- 球体被部分遮挡或位于画面边缘，但颜色和球体身份仍明确时，只紧贴框住可见部分，不凭空扩展到画面外。
- 无法确定是红球还是蓝球时，按 `K` 跳过留待复审，不能猜测类别。

### 4.2 门框

- 一个完整门框只画一个 `gate` 框，不要把每根 PVC 管分开标注。
- 边界框应覆盖构成可穿越矩形的红色 PVC 外轮廓，使框中心尽量接近门洞中心。
- 不包含门框下方的支撑腿、地脚、固定线和明显不属于矩形门框的附件。
- 门框被截断、遮挡或过于模糊，但仍能明确识别为比赛门时，框住可见门框整体；不能确认时按 `K`。
- 画面中同时出现高门和低门时，两个门分别画框，类别都是 `gate`，不再区分高门和低门类别。

### 4.3 尺寸与模糊底线

- 只要人眼能稳定判断类别和边界，即使目标较小也应标注。
- 目标小到无法稳定分类、严重拖影或与背景无法区分时，按 `K` 留待复审，不要按 `N`。
- 不要为了让框“好看”而加大边距。所有标注人员应采用相同的紧框标准。

## 5. 启动标注工具

标注工具在存放数据集的 Linux 图形桌面电脑上运行，不要在无图形界面的 Jetson FinalShell 终端中运行。

### 5.1 分别标注三个批次（当前推荐）

进入训练集目录：

```bash
cd /home/cjx/cjx_project/auv比赛/训练集/1
```

启动 `test1`：

```bash
./start_annotation_batch.sh test1
```

启动 `test2`：

```bash
./start_annotation_batch.sh test2
```

启动 `test3`：

```bash
./start_annotation_batch.sh test3
```

查看某个批次的进度和标签错误：

```bash
./start_annotation_batch.sh test1 --check-only
```

复查某个批次的已标注图片：

```bash
./start_annotation_batch.sh test1 --include-reviewed
```

三个批次的标签分别保存在各自图片目录下的 `labels/`，不会相互覆盖。选择分批标注后，不要再使用合并目录的 `start_annotation.sh`，否则会形成两套不同的标签进度。

## 6. 标注操作

1. 先观察整张图，找出所有红球、蓝球和门框。
2. 按 `1`、`2` 或 `3` 选择蓝球、红球或门框，界面上方会显示当前类别。
3. 按住鼠标左键从目标一角拖到对角，松开后得到待加入的框。
4. 按 `S` 加入该框。一张图有多个目标时，切换类别并重复画框。
5. 检查所有框和类别后，按 `Enter` 或 `D` 保存并进入下一张。

完整快捷键：

| 操作 | 按键 | 是否生成标签 |
|---|---|---|
| 选择蓝球 | `1` | 否 |
| 选择红球 | `2` | 否 |
| 选择门框 | `3` | 否 |
| 加入当前框 | `S` | 否，需继续保存图片 |
| 保存并下一张 | `Enter` 或 `D` | 是 |
| 确认无目标 | `N` | 是，生成空标签 |
| 存疑跳过 | `K` | 否，保留为未审核 |
| 撤销待选框/最后一框 | `Z` | 否 |
| 清空当前全部框 | `C` | 否，按 `Enter` 后才保存 |
| 上一张 | `A` | 否 |
| 退出 | `Q` | 否，不会保存未确认的当前图片 |

## 7. `N` 和 `K` 的区别

这是整个标注中最容易出错的地方：

- `N`：标注人员已经认真检查，确认画面中没有任何红球、蓝球或门框。程序会生成空 `.txt`，表示负样本。
- `K`：图中可能有目标，但颜色、边界或类别无法确认。程序不生成 `.txt`，留给组长或第二名标注人员复审。

有目标却误按 `N` 会让模型学到“这些目标是背景”，比少标一张图更严重。宁可按 `K` 留待复审，也不要猜测。

## 8. 保存、断点续标与复查

标签保存在：

```text
/home/cjx/cjx_project/auv比赛/训练集/1/merged_yolo_dataset/labels/
```

每张图的标签和图片主文件名相同：

```text
images/test2_frame_003270.jpg
labels/test2_frame_003270.txt
```

按 `Q` 退出后再次启动，工具会自动跳过已经存在标签文件的图片，从未审核图片继续。

复查所有已标注图片：

```bash
cd /home/cjx/cjx_project/auv比赛/训练集/1/merged_yolo_dataset
./start_annotation.sh --include-reviewed
```

查看标注进度、正负样本数量、三类目标框数量和格式错误：

```bash
./start_annotation.sh --check-only
```

交付前必须确认 `LABEL_ERRORS=0`。

不要在标注开始后重命名、移动或删除 `images/` 中的图片。多人标注时，不要同时操作同一份 `labels/` 目录，应由负责人先按 `test1_` / `test2_` / `test3_` 批次分工。

## 9. 标注人员交付前检查

交付前必须完成以下检查：

1. 没有把引导线、圆环、收集框标为 `gate`。
2. 没有把黄色/粉色高尔夫球、反光或气泡标为撞击球。
3. 红球、蓝球类别没有标反。
4. 门框是整体一框，而不是每根管子一框。
5. 所有框尽量紧贴目标，没有大量水体背景。
6. 同一张图中的所有目标都已标注，不是只标最大的一个。
7. 只有真正无目标的图片才使用空标签。
8. 所有无法确认的图片都使用 `K` 留待复审，没有猜测。

建议每名标注人员先试标 30 张，由负责人检查边界和类别一致性，确认合格后再继续整批标注。
